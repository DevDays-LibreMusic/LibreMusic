# Яндекс Музыка для Mornye / LibreMusic

Экспериментальное JavaScript-расширение для контракта Mornye 5.3.1.
Работает отдельно от Flutter и Rust приложения. Лицензия LGPL-3.0-only,
см. LICENSE, COPYING и NOTICE в корне репозитория и установочном архиве.

## Возможности

- Поиск треков, до 100 результатов первой страницы API.
- Метаданные: название и версия записи, исполнители, альбом, длительность,
  обложка, дата выпуска, номера дисков и треков, explicit и ISRC при наличии.
- Альбомы, включая несколько дисков.
- Плейлисты по пользователю и номеру либо UUID. Сокращённые записи треков
  догружаются пакетами по 50; порядок и повторы сохраняются.
- Скачивание полного MP3, если API разрешает его аккаунту: лучшее доступное
  качество до 320 kbps (включая 192 kbps) или строго 128 kbps. Превью отклоняются.
- Межсервисное сопоставление допускается только при совпадении ISRC.

Ссылки: домены `music.yandex.ru`, `.com`, `.by`, `.kz`, `.uz` и пути:

```text
/track/123
/album/456/track/123
/album/456
/users/username/playlists/789
/playlists/11111111-2222-3333-4444-555555555555
```

Параметры и фрагменты ссылок допускаются. Короткие ссылки, страницы артистов,
личная лента, «Моя волна», тексты и lossless в этой версии не реализованы.
Если API отдаёт неполный плейлист, расширение сообщает ошибку вместо
незаметного импорта его части. Ограничения времени выполнения задаёт Mornye;
очень большие плейлисты могут превысить их.

## Сборка и установка

Из корня LibreMusic:

```bash
node extensions/yandex-music/test.cjs
python3 extensions/yandex-music/build.py
python3 extensions/yandex-music/build.py --check
```

Результат: `.tmp/yandex-music-0.1.1.sflx`. Каталог `.tmp` игнорируется Git.
Сборка не требует сетевых запросов или сторонних Python/Node зависимостей.
Проверка `--check` сравнивает архив с текущими исходниками побайтово.

Импортируйте `.sflx` через установку расширения из файла в Mornye.
В настройках расширения укажите OAuth-токен своего аккаунта Яндекс Музыки,
затем включите расширение и выберите его для поиска и скачивания.
Полные загрузки зависят от доступа аккаунта, подписки и региона.

Получение токена описано в документации независимого клиента:
<https://ym.marshal.dev/token/>. Расширение не принимает пароль,
не выполняет вход через браузер и не обновляет токен автоматически.
Секретное поле сохраняется штатным механизмом настроек Mornye.
Токен передаётся только API, не добавляется к запросам CDN и не журналируется.
Не включайте реальные токены в тесты, исходники и отчёты об ошибках.

## Проверка

`test.cjs` выполняет исходный `index.js` в изолированном JS-контексте с
подставными ответами HTTP и файлового API. Проверяет формы запросов,
метаданные, ссылки, порядок плейлистов, ошибки авторизации, ограничения
загрузки, разрешённые CDN и отсутствие OAuth в запросах CDN.
Это офлайн-тесты, не проверка доступности сервиса или установленного приложения.

Для проверки на устройстве нужны собственный OAuth-токен и аккаунт:

1. Найдите трек и откройте его ссылку, альбом и оба формата плейлистов.
2. Скачайте доступный полный трек, проверьте длительность, формат и теги.
3. Проверьте недействительный токен, недоступный трек и отмену загрузки.
4. Убедитесь, что настройки сохраняются после перезапуска приложения.

## Протокол и совместимость

В 0.1.1 исправлены две ошибки, воспроизведённые на живом API: отказ от
полного MP3 192 kbps и проверка `ts` как десятичного числа. Теперь режим
`mp3-320` выбирает лучший доступный полный MP3 до 320 kbps, а шестнадцатеричное
`ts` переносится в ссылку без преобразования. ID качества сохранён для
совместимости с настройками 0.1.0.

API Яндекс Музыки не является публичным стабильным контрактом.
Эндпоинты сверены с первичными исходниками независимого клиента
[yandex-music-api](https://github.com/MarshalX/yandex-music-api):
`yandex_music/_client/{tracks,albums,playlists,_batch}.py` и
`yandex_music/download_info.py`. Реализация расширения написана отдельно;
Python-код и зависимости этого клиента в пакет не включены.

Используются `/search`, POST `/tracks`, `/albums/{id}/with-tracks`,
`/users/{user}/playlists/{kind}`, `/playlist/{uuid}` и
`/tracks/{id}/download-info`. Последний возвращает варианты MP3 и адрес XML
с параметрами временной ссылки. При изменении API этот путь может перестать
работать. Шифрованные потоки нового `get-file-info` не поддерживаются.

Контракт приложения: `rust_backend/crates/extensions/src/manifest.rs`,
`provider.js`, `prelude.js` и `manager/metadata.rs`.
Функции провайдера синхронные; используются `http`, `file.download`,
`utils.md5` и `registerExtension`. Поведение конкретного сервиса не добавляется
в ядро приложения.
