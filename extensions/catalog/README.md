# Каталог расширений LibreMusic

Эта папка содержит готовый репозиторий: `registry.json` и десять установочных
пакетов `.sflx` в `packages/`. Приложения с поддержкой JavaScript-расширений
Mornye/LibreMusic могут подключать его по HTTPS-ссылке на индекс.
Это не универсальный формат расширений для произвольных приложений.

## Подключение

После публикации этой папки в ветке `main` репозитория
`DevDays-LibreMusic/LibreMusic` откройте в приложении раздел репозитория
расширений, добавьте следующий адрес и установите нужные расширения:

```text
https://raw.githubusercontent.com/DevDays-LibreMusic/LibreMusic/main/extensions/catalog/registry.json
```

Используйте именно полный raw-адрес `registry.json`: обычный GitHub URL папки
приложение преобразует в адрес индекса в корне репозитория.
Локальное создание папки не публикует её в GitHub; до публикации адрес выше
не предоставляет этот каталог. Отдельные файлы из `packages/` уже можно
импортировать через локальную установку расширений.

## Состав и ограничения

Каталог включает собственные расширения из `extensions/`: Звук, VK Музыка,
КИОН Музыка, Яндекс Музыка, Deezer Direct, Amazon Music Direct,
YouTube Music Direct, Qobuz Direct, Tidal Direct и Beatport Direct.
Исторические копии `upstream-mornye/` сюда не включены: они имеют отдельный
каталог и могут дублировать сервисы с другими способами загрузки.

Пакеты экспериментальные. Amazon Direct предоставляет только каталог;
у остальных доступ к аудио зависит от сервиса, аккаунта и региона.
Настройки и ограничения приведены в README внутри каждого пакета и в
[документации расширений](../README.md). Учётные данные вводятся в приложении.
Проверка сборки и контрольных сумм не подтверждает работу живых API или
воспроизведение на устройстве.

## Обновление

Из корня репозитория:

```sh
python3 extensions/build_catalog.py
python3 extensions/build_catalog.py --check
python3 -m unittest discover -s extensions/tests -p 'test_catalog.py'
```

При изменении поведения расширения обновите версию в его `manifest.json`,
пересоберите каталог и включите исходники, пакеты и индекс в один PR.
Сборщик не обращается к сети; архивы воспроизводимы, а индекс содержит SHA-256
каждого пакета. Токены и пользовательские настройки в архивы не попадают.
`--check` обнаруживает отсутствующие, изменённые и лишние пакеты.

Для другого HTTPS-хостинга или ветки задайте адрес **папки каталога**:

```sh
python3 extensions/build_catalog.py --output-dir .tmp/catalog --base-url https://example.org/extensions
python3 extensions/build_catalog.py --output-dir .tmp/catalog --base-url https://example.org/extensions --check
```

Разместите весь результат на указанном адресе и подключите
`https://example.org/extensions/registry.json`. Индекс использует абсолютные
адреса пакетов, поэтому при переносе на другой адрес его нужно пересобрать.
